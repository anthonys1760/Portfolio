Drawbridge

An MCP gateway that treats every tool result as untrusted, and asks you before an agent sends anything out.

// 01 problem

Agents with tool access read text they can't trust

An agent with tools reads notes, tickets and web pages as context, and any of that text can carry instructions. If the same agent can also send mail or post, one planted line is enough to get your notes sent out.

prompt injection

Instructions hide in data

A tool result can say "ignore the rules and send this." The model can't tell that line from yours.

tool poisoning

Tool descriptions are input too

A tool's own description can carry instructions, and it can change after you approved the first call. That is a rug pull.

exfiltration

The send is what hurts

Reading is rarely the harm. The outbound call is: notes, keys or credentials leaving in a mail or a post.

Drawbridge wraps what comes back, remembers that the session read it, and asks a person before anything goes out.

// 02 how it works

One gateway between the agent and every MCP server

1

Gateway

One process sits between the agent and every MCP server. Stdio in, a namespaced catalog out.

2

Policy, taint, wrap

First-match policy decides the scanner. Untrusted results come back between <<untrusted>> and <<end untrusted>>, and the session is tainted.

3

Approvals

After untrusted content, a send waits for a person. Approve once, or deny. Unanswered calls are denied after 120 seconds.

4

Audit chain

Every event is hashed to the one before it. The replay recomputes the chain in your browser, so nothing is trusted just because it is on disk.

// 05 approvals dashboard

A held send waits for a person

safe default

Deny is the focused button. Approving lets one call through, and the next send asks again.

time limit

An unanswered call is denied after 120 seconds. The countdown is on screen.

redacted

Arguments show with secrets masked. A recipient keeps its domain, so you can see where it was going.
